# ValutaTrade Hub

Консольный симулятор валютного портфеля. Приложение хранит пользователей и
балансы в JSON, получает курсы фиатных валют и криптовалют и рассчитывает
стоимость портфеля в выбранной валюте.

## Установка и запуск

Нужны **Python 3.12+**, **uv** и Git. Команды ниже выполняются из корня проекта.

```bash
uv sync --locked
uv run valutatrade
```

Равнозначные варианты запуска:

```bash
make install
make run
uv run python main.py
uv run python -m valutatrade_hub
```

`uv run valutatrade --help` выводит список команд, `--version` — версию пакета.
Для команд, требующих входа, используйте интерактивный режим: сессия хранится
в памяти до `logout` или завершения программы.

## Пример работы без API-ключа

После `uv run valutatrade` введите:

```text
register --username alice --password demo1234
login --username alice --password demo1234
update-rates --demo
buy --currency BTC --amount 0.05
buy --currency EUR --amount 200
sell --currency BTC --amount 0.01
show-portfolio
show-portfolio --base EUR
get-rate --from USD --to BTC
show-rates --top 2
show-rates --currency RUB
sell --currency BTC --amount 100
get-rate --from ABC --to USD
exit
```

`--demo` явно включает фиксированные **учебные курсы**, не текущие рыночные
котировки. Источник сохраняется как `Demo (synthetic)` и отображается при
выводе курса. Демо-режим не включается автоматически при сетевых ошибках.
Начальные JSON-файлы пустые: тестовые пользователи не входят в поставку.

Пароль можно не указывать в команде: приложение запросит его через `getpass`
без отображения вводимых символов. Пароли в примере предназначены только для
локальной демонстрации.

## Модель операций

После регистрации портфель пуст. `buy` увеличивает баланс выбранной валюты,
`sell` уменьшает его. Списание с USD-кошелька и зачисление выручки в USD
не выполняются. Оценочная стоимость `amount × rate` используется только для
вывода: стартовый капитал и команда пополнения не нужны.

Количество `--amount` задаётся **в единицах выбранной валюты**. Например,
`buy --currency BTC --amount 0.05` добавляет 0.05 BTC. Продажа сверх остатка
отклоняется; портфель не меняется. Нули, отрицательные числа, `nan`, `inf`
и неизвестные валюты отклоняются. Отдельной истории транзакций нет:
BUY/SELL регистрируются декоратором в `logs/actions.log`.

Внутренние суммы — `float`, как предусмотрено заданием. Это учебный симулятор,
не система реальных денежных расчётов.

## Команды

| Команда | Аргументы | Действие |
| --- | --- | --- |
| `register` | `--username`, `--password` (необязательно) | Регистрация |
| `login` | `--username`, `--password` (необязательно) | Вход |
| `logout` | — | Завершение сессии |
| `show-portfolio` | `--base USD` | Балансы и суммарная стоимость |
| `buy` | `--currency BTC --amount 0.05` | Увеличить баланс |
| `sell` | `--currency BTC --amount 0.01` | Уменьшить баланс |
| `get-rate` | `--from EUR --to USD` | Прямой и обратный курсы |
| `update-rates` | `--source coingecko` или `--source exchangerate` | Обновить выбранный источник |
| `update-rates` | без аргументов | Обновить оба источника |
| `update-rates` | `--demo` | Загрузить учебные курсы |
| `show-rates` | `--currency RUB`, `--top 2`, `--base EUR` | Фильтрация снимка курсов |
| `currencies` | — | Поддерживаемые валюты |
| `help`, `exit` | — | Справка и выход |

`buy` и `sell` дополнительно принимают `--confirm`: перед сделкой
запрашивается подтверждение `y/n`. Для справки по аргументам:
`buy --help`, `get-rate --help` и т.д. Имена с пробелами заключаются в кавычки.
`--top` выбирает наиболее дорогие **криптовалюты по цене единицы**,
а не по капитализации.

## Parser Service

### Источники

- [CoinGecko Simple Price](https://docs.coingecko.com/v3.0.1/reference/simple-price)
  — BTC, ETH, SOL. При необходимости задайте `COINGECKO_API_KEY` для Demo API.
- [ExchangeRate-API v6](https://www.exchangerate-api.com/docs/standard-requests)
  — EUR, GBP, RUB. Требуется личный `EXCHANGERATE_API_KEY`.

Ключи передаются через окружение. Пример для bash/zsh с вводом ключа без
появления его значения в истории команд:

```bash
read -rs EXCHANGERATE_API_KEY
export EXCHANGERATE_API_KEY
uv run valutatrade update-rates
```

После первой команды введите ключ и нажмите Enter. `.env.example` содержит
имена переменных; `.env` не читается автоматически и исключён из Git.
В PowerShell переменные задаются через `$env:ИМЯ_ПЕРЕМЕННОЙ`.

Клиенты имеют общий интерфейс `fetch_rates() -> dict`. Запросы ограничены
таймаутом 10 секунд. Ошибки авторизации, лимитов, сети и формата ответа
преобразуются в `ApiRequestError`. Сообщения сетевых ошибок не содержат URL
с ключом. Отказ одного источника не мешает сохранить результат другого.
При отказе всех источников предыдущий снимок сохраняется.

В ответе ExchangeRate-API используется `conversion_rates`. Значение EUR при
`latest/USD` означает количество евро за доллар. Для `EUR_USD` сохраняется
обратное значение: `1 / conversion_rates["EUR"]`. Также поддерживается
поле `rates` из примеров задания.

### Кэш и история

- `data/rates.json`: `pairs` с последними значениями и `last_refresh`.
- `data/exchange_rates.json`: список наблюдений с парой, временем и источником.
- Новая запись заменяет снимок только при более свежем `updated_at`.
- Повторное наблюдение с той же парой и меткой времени не дублируется.
- Каждый JSON записывается через временный файл, `fsync` и `os.replace`.
- История записывается перед снимком; повтор после ошибки не дублирует запись.

`get-rate` читает кэш. Если курс отсутствует или устарел, выполняется одна
попытка обновления Parser Service, затем повторное чтение. При неудаче
возвращается `ApiRequestError` с предложением повторить запрос или выполнить
`update-rates`. Аналогичную проверку используют сделки и оценка портфеля.
`show-rates` просматривает локальный снимок без сетевых обращений и помечает
устаревшие пары сообщением об ошибке.

TTL по умолчанию — **300 секунд**. Время котировки берётся из ответа API,
если оно есть; иначе используется время получения. Если поставщик отдаёт
котировки реже TTL, даже успешное обращение может не сделать курс свежим.
TTL можно увеличить под частоту обновления источника; возраст котировок
не маскируется новым временем запроса.

Прямые и обратные курсы поддерживаются непосредственно, кросс-курсы
вычисляются через USD. Для пары `X_X` курс равен 1. Снимок кратковременно
кэшируется замыканием; изменение файла сбрасывает ключ кэша, а TTL курса
проверяется при каждом обращении.

### Планировщик

```bash
uv run python -m valutatrade_hub.parser_service.scheduler --interval 300
uv run python -m valutatrade_hub.parser_service.scheduler --once --source coingecko
```

Остановка цикла — Ctrl+C. Для воспроизводимой проверки поддерживается `--demo`.
JSON-хранилище рассчитано на локальную последовательную работу: не запускайте
несколько пишущих процессов с одним каталогом данных одновременно.

## Настройки и логи

`SettingsLoader` и `DatabaseManager` — singleton через `__new__`.
Настройки читаются из `[tool.valutatrade]` в `pyproject.toml`. Можно указать
другой TOML-файл через `VALUTATRADE_CONFIG`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VALUTATRADE_DATA_DIR` | `data` | Каталог JSON |
| `VALUTATRADE_LOG_DIR` | `logs` | Каталог логов |
| `VALUTATRADE_RATES_TTL` | `300` | TTL в секундах |

Относительные пути отсчитываются от текущей рабочей директории.
После установки wheel приложение само создаёт файлы при первой записи.
Регистрационные данные хранятся с солью и SHA-256 согласно заданию;
`get_user_info()` не раскрывает соль или хеш.

Логи — JSON Lines: `actions.log` с уровнем INFO, `parser.log` с уровнем DEBUG.
Один логгер парсера пишет подробности в файл; на время `update-rates`
добавляется консольный обработчик INFO с коротким форматом. Автообновление
из `get-rate` пишет только в файл. Файл содержит имя логгера, HTTP-статус,
время ответа и traceback ошибок; API-ключи маскируются. Итог команды печатает CLI.
Ротация: 1 МиБ, до трёх резервных файлов. Декоратор `@log_action` фиксирует
время, действие, пользователя, валюту, сумму, курс, результат и ошибку;
в подробном режиме — баланс до и после. Исключения пробрасываются в CLI.

## Проверка и сборка

```bash
make check                  # Ruff + форматирование + pytest
make format                 # форматирование исходников
make build                  # wheel и sdist в dist/
```

Без Make: `uv run ruff check .`, `uv run ruff format --check .`,
`uv run pytest -q`, `uv build`.

Тесты работают во временных каталогах, сетевые ответы заменяются контролируемыми
фикстурами. Проверяются модели, сессии, JSON, отрицательные суммы, TTL,
автообновление, инверсия фиатных курсов, частичный отказ API, отмена операции
и полный сценарий CLI. Реальный API-ключ для запуска тестов не нужен.

Проект ведётся в Git: `main` — стабильная версия, изменения разрабатываются
в отдельной ветке и объединяются после проверок. Виртуальное окружение,
артефакты сборки, логи и секреты исключены через `.gitignore`.

## Демонстрация

[Запись терминала в формате asciinema](docs/demo.cast) — реальный запуск CLI
с регистрацией, входом, покупкой/продажей, портфелем, курсами, обновлением
и ошибками. Запись использует явно отмеченные учебные курсы.

```bash
asciinema play docs/demo.cast
```
